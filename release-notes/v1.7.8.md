# v1.7.8 — The App That Always Opens

**Released:** 2026-11-03

- THE APP THAT ALWAYS OPENS (the owner's word, 03/11: 'o app nao abre, eu inicializei aqui e ele nao abriu, veja isso ate que realmente tenha uma prova que resolveu o problema'). The v1.7.7 diagnostics found NOTHING wrong with the binary itself — the leader reproduced the whole failure ladder in a sandbox and rebuilt the boot path so the window ALWAYS comes up:
- BOOT LADDER (persistent, survives relaunch and update; lives in userData/boot-escada.json): L0 normal -> L1 --disable-gpu -> L2 + --disable-dev-shm-usage -> L3 + --no-zygote (REPRODUCED and CURED in the leader's sandbox: renderer death-loop by zygote in restricted namespace) -> L4 + forced X11. The step goes UP whenever the renderer insists on dying (3x crash, 3x failed load, 2x watchdog, gray-window detection) and NEVER goes down on its own — the owner's stability beats aesthetics. At max level the app shows a NATIVE dialog with the boot.log path and keeps trying.
- GRAY-WINDOW DETECTOR (new): page finished loading but painted nothing? 25s after load the main process counts the DOM children — empty body escalates the ladder; live body sends an 'ui-viva' beacon. The 'tela cinza pos-update' the owner reported on 01/11 now has a cure that measures itself.
- REMOTE BOOT TELEMETRY (the proof the owner asked for): the MAIN process (which boots even when the renderer dies) sends small beacons to the house relay at every milestone and every stumble — boot-start, boot-completo, ui-viva, escada-escalou, nivel-maximo, disco-baixo. If the app ever fails to open again, the whole boot.log arrives at the relay WITHOUT asking the owner for anything. Beacon key is write-only; reading requires the agent token. Capped at 12 beacons/boot, 4s timeout, never blocks boot.
- RENDERER CONSOLE AS EVIDENCE: warnings/errors from the page are now logged in main.log ([renderer:erro]...) — a JS-dead page used to be invisible.
- DISK-FULL CHECK at boot: <200MB free in userData is measured, logged, beaconed and warned in a native dialog (classic silent boot killer).
- FUSE-FREE INSTALLER: the release now ships GalaxyCut-AI-1.7.8-Linux-Instalador.sh — a self-extracting script (bash + tar) that installs to ~/.local/opt/galaxycut-ai, creates the menu entry and launches. On distros without libfuse2 (Ubuntu 24.04+) the AppImage dies silently on double-click; the.sh needs nothing but bash. The AppImage remains for FUSE-capable machines.
- /dev/shm pre-check: hostile /dev/shm is detected at module load and cured with --disable-dev-shm-usage regardless of ladder level.
- boot.log path comment fixed (the real dir is ~/.config/galaxycut-ai, lowercase).
