# v1.7.9 — The AppImage Without FUSE

**Released:** 2026-11-03

- THE APPIMAGE WITHOUT FUSE — the real cure for 'o app nao abre' (owner's word, 03/11: 'na vdd é pra você fazer um appimage em galaxycut-ai-releases'). The field evidence closed the case: ZERO boot beacons ever arrived from the owner's machine, meaning the AppImage runtime dies BEFORE Electron exists — dlopen: error loading libfuse.so.2, the silent double-click killer on every modern distro that ships without libfuse2 (Ubuntu 22.04+/24.04+, Mint 21+, Fedora, Arch). v1.7.8's.sh installer was the detour; the owner asked for the AppImage itself to open.
- CUSTOM RUNTIME, SAME STANDARD FORMAT: we compile our own AppImageKit type-2 runtime (squashfuse 1f98030 + AppImageKit dlopen patches + OUR patch) — when /dev/fuse is missing or libfuse.so.2 fails to load, the runtime no longer exits: it re-executes itself with --appimage-extract-and-run and uses the built-in extraction path (content-aware cache dir, works on any Linux with just bash and /tmp). When FUSE IS present, nothing changes: it mounts exactly like before. The file remains a 100% standard AppImage (magic AI\x02, type 2, gzip squashfs) — AppImageLauncher/appimaged compatible.
- THE RUNTIME IS TINY AND HONEST: gc-no-fuse-1.7.9, ~190KB, dynamically linked against libc only (xz and zlib linked statically, like upstream). It answers --appimage-version with its build tag so field diagnostics can always tell which runtime a machine is running.
- PROVEN BEFORE SHIPPING (the owner's rule): the no-FUSE sandbox reproduced the exact failure of the owner's PC (v1.7.8 AppImage → dlopen error, exit 1, zero beacons); the same sandbox then ran the repacked AppImage with the new runtime → fallback message, extraction, AppRun executed, exit 0. The full E2E (real app, real boot beacons, ui-viva) runs before the release is published — if it doesn't open here, it doesn't ship.
- PIPELINE: the AppImage is now built in two steps — electron-builder packs the app as usual, then scripts/repack-appimage-runtime.sh swaps in the no-FUSE runtime (extract official AppImage → appimagetool --runtime-file runtime-gc → gzip). The.sh installer and the tar.gz remain unchanged escape hatches for any machine, FUSE or no FUSE.
