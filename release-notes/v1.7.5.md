# v1.7.5 — The Render Percentage Never Dies

**Released:** 2026-11-02

- THE RENDER PERCENTAGE NEVER DIES: you asked for it straight — '% when the video is being rendered, otherwise the person thinks it froze'. The engine had real progress, but between its events the bar could sit STILL for seconds at a time: loading a big video file (one tick per file, up to 20 s of silence), decoding each audio track (one tick per file), the loudness measurement, the mux sitting at 96–98%, and the native save dialog + disk write at the very end. Now every long stage reports fine-grained progress: the media preload announces WHICH file is loading (with its position, e.g. 3/17) and the bar creeps WITHIN each item while it loads; each audio decode announces its file; the loudness measurement is confessed; the audio encode walks 96→97.5%; the final flush gets its own stage. And the UI gained a heartbeat that depends on NOTHING: an elapsed-seconds counter ticking every half second from the first click, so even when the engine is quietly working the screen is alive.
- PERCENTAGE FROM THE VERY FIRST CLICK: the export hub used to show a mute '—' until the engine's first event (which could take seconds on codec probing). Now it shows an honest 0% immediately, the bar never has zero width, and it breathes (pulse) in every non-rendering phase — preparing, muxing, saving. The footer button itself carries the live percentage ('Renderizando… 43%'), so the number stays visible even when the settings list is scrolled above the progress block. A new phase 'Salvando arquivo…' tells you the file is being written to disk — the last silent stretch that looked like a freeze.
- THE OLD EDITOR'S EXPORT GOT THE SAME HEART: the classic editor's export dialog (the one with frame counter, ETA and speed) now shows the elapsed seconds next to the percentage too — both export surfaces share the same engine, so both benefit from the finer ticks, and neither can look frozen while it works. Plus a small honest fix: the error toast in the export hub used a stale title variable on the first failure (empty title toast) — it now uses the local title it just built.
