# v1.7.6 — Clips Are Born Where They Belong

**Released:** 2026-11-02

- CLIPS ARE BORN WHERE THEY BELONG (the field wound of the GTA 6 test, 01/11): timeline_add_clip used to create EVERYTHING at the default position, forcing the AI into a second timeline_update_clip per element — which it kept forgetting, and the leader ended up hand-fixing 20+ clips through the bridge. Now the clip is BORN positioned: position ('top'/'center'/'bottom' or a 0.02–0.98 fraction of the frame top), x (−1..1, 0 = center), zoom_pct (40..200) and volume (0.05..2.0) are applied AT CREATION with posLock, and a music bed can be born already renamed music_* at 0.7 (≈ −3 dB). One call per element: your layered frame mounts the photo, the bottom-anchored character and the music bed in three calls, zero fix-ups (your style skill owns the constants; the app owns the ruler). An invalid position refuses BEFORE anything is created — the refusal teaches the ruler and points to the style skill.
- THE AI CAN FINALLY SEE WHERE EVERYTHING SITS: timeline_get_clips reported position only for captions — photos, the character and motion graphics were INVISIBLE to the audit, so 'fix positions before rendering' (the exclusive-zones rule of your style skill) was blind guesswork. Now EVERY clip reports position {x, y, frac_top, locked} (frac_top = the same fraction the position param takes, so the AI reads in the same ruler it writes) plus its real volume — the music bed at 0.7 is auditable, not a promise.
- STOCK B-ROLL IS BORN POSITIONED TOO — AND TWO REGISTRY LIES DIED: visual_insert_broll gained the same position/x/zoom_pct at creation. The x parameter's doc claimed '0..1, default 0.5 = center' while the code clamps −1..1 with 0 = center — an AI following the doc would shove every element off-center; and 'bottom' was documented as 0.62 (the EDITOR's y convention) when the tool actually takes 0.81 from the top. Both docs now tell the truth. And the position finally REACHES THE RENDERED VIDEO: the export bridge used to pin every media clip at x:0,y:0 — the audit saw the zone, the exported video drew everything centered. The bridge now carries x/y/posLock for media and motion graphics, and the harness preview draws images with the SAME math as the export (contain-fit × zoom + position) instead of a glued-to-the-frame cover-fit.
