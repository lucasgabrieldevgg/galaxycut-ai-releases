# v1.7.4 — The Export Sees The Agent's Timeline

**Released:** 2026-11-02

- THE EXPORT SEES THE AGENT'S TIMELINE — FIXED: the field test (Nov 1st) had the agent build a full 41-clip timeline, the export hub open 'synced', and the engine still say 'nothing to export — empty timeline'. Root cause, measured: the export reads the playback clock's duration, and that duration was only recomputed by the old editor's preview stage — a surface the agent workspace never mounts, so after the sync the clock stayed at zero and the engine saw an empty timeline. The bridge now sets the duration itself, in the same door as the snapshot, using the exact same ruler the playback uses (idempotent with the editor). A new proof (C3b) asserts the real playback state after the sync — and the contrast test confirms it fails on the pre-fix code (0s) and passes now (45s).
- THE AI CAN NOW SET A CLIP'S VOLUME: timeline_update_clip gains a volume parameter (0.05..2.0; 1 = unity, 0.7 ≈ −3 dB). It writes the REAL clip volume — the one the preview AND the export mix read (same field, one truth). This closes the 'background music came out silent' wound: until now the AI had no way to level an imported music file (volume existed only for synthesized SFX and procedural tracks), and the procedural default (−24 LUFS) plus auto-ducking (−14 dB under continuous speech) left the bed at ≈ −38 LUFS — inaudible. The recipe for Luke's format now lives in his skill v1.6: HIS music file, renamed music_*, volume 0.7, NO ducking.
- HONEST EMPTY-TIMELINE MESSAGE: the export hub's 'empty timeline' text still claimed the bridge integration was 'pending' (stale wording) — it is not; the bridge syncs for real. The message now teaches the actual situation: if it appears, the snapshot arrived empty and re-opening the export hub is the path.
